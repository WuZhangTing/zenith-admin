# Zenith Admin

[![Version](https://img.shields.io/github/v/tag/iwangbowen/zenith-admin?label=version&color=blue)](https://github.com/iwangbowen/zenith-admin/releases)
[![Pages](https://github.com/iwangbowen/zenith-admin/actions/workflows/pages.yml/badge.svg)](https://github.com/iwangbowen/zenith-admin/actions/workflows/pages.yml)
[![Release](https://github.com/iwangbowen/zenith-admin/actions/workflows/release.yml/badge.svg)](https://github.com/iwangbowen/zenith-admin/actions/workflows/release.yml)
[![License](https://img.shields.io/github/license/iwangbowen/zenith-admin)](./LICENSE)

基于 **Hono v4 + React 19 + Semi Design v2 + Drizzle ORM** 的全栈后台管理系统。涵盖认证授权（OAuth / 企业 SSO）、组织架构（含通讯录同步）、权限控制、系统配置、通知中心（事件驱动多渠道触达）、消息中心（IM / 音视频通话）、日志审计、告警中心、在线会话、定时任务、文件存储、缓存管理、低代码工作流、规则引擎、智能助手（Mastra 驱动的 AI 对话 / 智能体 / RAG 知识库）、数据分析、报表中心（BI）、支付中心、会员体系（含 C 端门户）、公众号管理、开放平台、CMS 内容管理、知识中心（Wiki）、服务器运维（Web 终端 / SSH / Docker）等完整业务场景，并内置可选的 **多租户（Multi-Tenant）** 与 **License 授权** 支持。

项目采用 **npm monorepo** 结构：后端使用 Hono + PostgreSQL 提供 RESTful API，前端使用 React 19 + Vite + Semi Design v2 构建界面，`shared` 包统一维护前后端共享类型、常量与 Zod 校验 schema。

## 功能模块

### 认证与账户安全

- **登录注册**：账号密码登录、图形验证码校验、注册开关全局控制、找回密码（邮箱重置）
- **OAuth 第三方登录**：支持 GitHub、钉钉、企业微信、飞书一键登录与账号绑定
- **OAuth2 授权服务**：内置 OAuth2 应用管理与 RFC 合规标准端点（userinfo / introspect / revoke），可作为第三方系统的统一登录中心
- **企业身份源（SSO）**：OIDC / SAML / LDAP / AD 企业级单点登录接入，支持 JIT 自动建号
- **身份安全**：身份安全策略集中配置与登录风险事件查看
- **JWT 鉴权**：Access Token + Refresh Token 双 Token 机制，自动静默续期
- **密码策略**：复杂度规则（最小长度、大写字母、特殊字符）+ 密码过期强制修改
- **登录安全**：登录失败次数限制 + 账号自动锁定（基于 Redis 计数），管理员可解锁
- **API Token**：个人 API Token 创建与管理，用于第三方接口调用鉴权

### 权限与组织架构

- **用户管理**：CRUD、启停用、角色/部门/岗位分配、批量操作、Excel 批量导入（含模板下载）、管理员重置密码、用户级直接菜单授权与有效权限预览
- **角色管理**：CRUD、菜单权限树形分配（父子不联动精确授权，勾选页面自动带上「查询」权限点）
- **菜单管理**：目录 / 菜单 / 按钮三级能力模型，**显示与操作解耦**——目录/菜单为纯显示资源，全部权限码（含查询）由按钮型权限点承载；支持外链与 iframe 内嵌页面；虚拟化树形表格流畅维护近千节点
- **动态菜单路由**：前端根据用户角色自动注册可访问页面，实现路由级权限隔离
- **按钮级权限**：基于 `usePermission` Hook 的细粒度前端编程式权限控制
- **数据权限**：全部 / 自定义 / 本部门 / 本部门及以下 / 仅本人五种数据范围
- **用户组**：跨部门用户分组与成员分配，组绑定角色自动继承；支持动态用户组——成员按部门 / 岗位规则自动物化，权限 / 工作流 / 报表 ACL 等消费方零改动生效
- **部门管理**：树形组织层级维护
- **岗位管理**：岗位信息维护与用户关联
- **通讯录同步**：从 LDAP/AD、钉钉、企业微信、飞书同步组织架构与人员，支持字段映射、冲突三策略裁决、离职自动禁用与熔断保护；平台事件回调准实时增量，内置 SCIM 2.0 Server 承接 Azure AD / Okta 推送

### 系统配置与安全

- **系统配置**：验证码开关、密码策略、注册控制、登录失败锁定等核心行为动态配置
- **IP 访问控制**：白名单/黑名单双模式，支持 CIDR 网段，配置热更新缓存，附访问日志
- **数据脱敏**：手机号 / 邮箱 / 身份证 / 姓名 / 银行卡 / 自定义规则的字段脱敏
- **接口限流**：高危接口请求频率限制（基于 Redis 计数），规则可视化管理
- **幂等防重复提交**：基于 Redis 的接口幂等拦截，支持客户端 Token 与服务端自动指纹两种模式
- **维护模式**：一键开启站点维护，支持白名单放行
- **标签管理**：统一标签体系，供多业务对象复用
- **意见反馈**：用户反馈收集、处理状态流转与回复
- **邮件 / 短信 / OAuth 配置**：SMTP 服务器、短信服务商、第三方登录 Client ID/Secret 配置与发送测试
- **数据字典**：字典类型与字典项统一管理，前后端共用

### 通知与消息

- **通知公告**：富文本（wangEditor）编辑、发布/草稿状态控制、已读记录管理、批量操作
- **事件驱动通知中心**：类型安全的统一事件目录 + `notify()` 唯一派发入口，渠道选择、订阅偏好、免打扰、幂等与留痕全部由派发层收口
  - 渠道适配：站内信 / 邮件 / 短信 / Webhook / 聊天卡片五通道，统一模板（变量占位符）与发送记录
  - 可靠投递：Outbox 事务内登记 + 低延迟派发 + 定时兜底补投，投递归因日志可解释「为什么没收到」
  - 用户偏好：「事件 × 渠道」订阅偏好矩阵、全局静音、按时区免打扰时段、邮件摘要聚合（实时 / 每小时 / 每日）
  - 管理策略：平台 / 租户两级渠道覆盖与锁定、退订合规链接（RFC 8058 One-Click）
- **消息频道**：系统号 / 运营号订阅体系，群发消息（富文本图文 / 草稿 / 定时 / 撤回）、频道菜单与自动回复、客服工作台（会话聚合 / 快捷回复 / 满意度 / 绩效统计）、频道数据看板
- **个人消息**：「我的消息」收件箱与「公告中心」个人页，导航未读徽标全布局展示
- **实时推送**：基于 WebSocket 的新通知实时推送，前端自动重连（指数退避）
- **消息中心（IM）**：内置即时通讯，单聊/群聊、语音消息、WebRTC 音视频通话、投票、消息转发（逐条/合并）、@提及、表情回应、卡片消息、未读计数、会话置顶与收藏、媒体库、消息搜索、聊天记录导出
- **Webhook 机器人**：自定义入站 Webhook 机器人，接收并处理卡片消息

### 日志与审计

- **登录日志**：记录登录行为（IP、浏览器、地理位置、状态），支持全局与个人视图及统计面板
- **操作日志**：记录关键业务操作轨迹，支持变更前后字段 Diff 对比、变更内容 / 请求体全文检索及统计面板
- **日志文件**：服务端 Winston 日志文件在线查看与下载，支持正则 / grep 搜索、级别筛选、实时追踪（可暂停续传）与告警联动跳转
- **在线会话**：查看当前所有在线会话（Redis 持久化），支持强制下线并实时推送退出消息

### 文件与存储

- **文件管理**：文件上传、列表查询、下载、删除及文件统计
- **可视化文件管理器**：类资源管理器的目录浏览、上传进度、在线预览
- **多存储后端**：本地、阿里云 OSS、腾讯云 COS、华为云 OBS、七牛云 Kodo、百度云 BOS、Azure Blob、S3 兼容、SFTP 共九种
- **默认存储切换**：通过存储配置页面一键切换当前默认存储策略

### 任务与运行维护

- **定时任务**：Cron 任务 CRUD、可视化 Cron 表达式构建器、手动立即执行、启停控制、执行历史日志（基于 pg-boss）
- **任务中心**：统一异步任务框架（批量导入/导出、报表生成、静态化等长耗时操作），带进度推送、断点续跑、自动重试、取消与行级明细，支持按 payload / result 内容检索与多维统计
- **系统调度**：系统内置调度任务面板，任务配置与手动触发、运行记录、失败告警确认、调度节点视图
- **导出中心**：各模块异步导出任务统一管理与文件下载
- **数据保留**：全库日志与流水表保留策略集中配置，每日定时清理，支持试算预览
- **数据库备份**：基于 pg_dump 的手动备份，支持下载与删除，可结合定时任务自动化
- **数据库管理**：在线 SQL 控制台、表数据编辑、ER 关系图、对象管理、运维面板（物化视图刷新、活动连接、表维护、索引健康、结构校验）
- **缓存管理**：Redis 缓存可视化查看、按 Key 模式搜索、分类展示、支持单条/批量删除
- **系统监控**：服务器实时状态（CPU、内存、Node.js 版本、运行时长）+ 历史趋势 + 温度传感器
- **健康检查**：`GET /api/health` 服务探活；内置 Prometheus 指标与 OpenTelemetry 链路追踪

### 告警中心

- **告警规则**：基于阈值的告警规则引擎，覆盖基础设施（CPU / 内存 / 磁盘 / 网络 / QPS / HTTP 错误率 / 日志 ERROR·WARN 频率）、工作流健康度、支付与开放平台四类共 30 项指标
- **触发机制**：持续 N 分钟超阈触发、自动恢复解除、静默期防轰炸，支持试发通知验证配置
- **多通道触达**：邮件 / Webhook / 站内信 / 群机器人
- **告警事件**：按指标 / 级别 / 状态筛选与导出，认领与处理闭环；日志类告警可一键跳转日志文件定位现场
- **告警概览**：全局告警态势看板

### 服务器运维（DevOps）

- **Web 终端**：浏览器内 xterm.js 终端，多标签 / 分屏，主题可配
- **SSH / SFTP**：SSH 连接配置管理、远程 SFTP 文件浏览与权限修改
- **终端录屏 / 终端会话**：会话录制回放与活动会话管理
- **进程 / 端口 / 服务**：进程管理（工作目录、环境变量）、端口监听、systemd 服务管理
- **Docker**：容器 / 镜像查看与管理
- **网络诊断**：Ping、DNS 查询、HTTP 探测等工具
- **防火墙 / Nginx / SSL**：防火墙规则管理、Nginx 站点配置、SSL 证书查看与管理
- **日志查看器**：服务端日志实时跟踪

> 运维能力依赖宿主机环境（node-pty、ssh2、dockerode 等），建议在受控的服务器环境启用。

### 低代码工作流引擎

- **审批中心**：发起工作台（按分类快速发起）、待我审批（通过 / 驳回 / 转办 / 委派 / 加签减签 / 退回 / 催办 / 手写签名）、我的申请、抄送我的、我已办、审批代理（直接代批 / 建议制双模式）；时间线按表单求值展示预测剩余路径，多人节点展示审批进度徽标
- **流程定义**：工作流 CRUD、分类管理、版本管理与差异对比、导入/导出、草稿/发布/禁用、流程模板库
- **可视化设计器**：发起人 / 审批 / 办理 / 抄送 / 条件分支 / 路由分支 / 延迟器 / 触发器 / 子流程等节点编排，支持条件编辑、操作与表单权限配置、节点监听器、撤销重做
- **表单设计器**：拖拽式自定义表单（表单库 + 表单渲染 + 远程数据源）；业务表单支持三种接入方式：表单库设计器 / 自定义业务表单 / 业务系统主导（businessKey 关联外部实体）
- **流程自动化 / 定时发起**：基于触发条件的自动化规则（动作执行留痕可核对）与 Cron 定时发起流程实例（支持表单数据预填）
- **事件订阅 / 触发器 / 连接器**：Webhook 订阅端点管理、触发器执行记录、外部系统连接器统一外呼，支持外部审批回调与补偿 / Saga 编排
- **流程监控**：实例监控与跨实例任务监控双视角、流程轨迹与流转记录、统计分析、逾期任务、离职交接与导出
- **健康巡检**：积压、死信、失败率、卡死实例等引擎健康指标检测，接入告警中心
- **移动审批**：独立移动端审批轻页（`approval.html`），不加载后台框架即可处理审批

> 详见文档站：[工作流引擎](https://iwangbowen.github.io/zenith-admin/workflow/)。

### 规则中心

- **决策表 / 决策流**：可视化规则编排与执行，支持命中策略、版本管理与差异对比、测试用例、影子运行对比与决策执行记录追溯
- **名单库**：黑 / 白 / 灰名单集中管理，供风控与业务规则引用

### 智能助手（AI · Mastra 驱动）

- **模型接入**：基于 Mastra 模型目录接入 178+ 服务商与私有 OpenAI 兼容网关，多级模型降级链（5xx / 限流 / 超时自动切换）；支持用户级个人 AI 配置（与系统服务商配置同构）
- **智能对话**：多会话流式对话，支持思维链透出（七档推理力度）、图片消息（vision / 粘贴截图上传）、语音输入（STT）与朗读（TTS）、Markdown 渲染、PDF 文档预览、实际模型标注、多模型对比投票（竞技场）、消息导出（Markdown / JSON）、对话分享（公开只读链接）、点赞/反馈闭环
- **记忆与上下文**：Mastra Memory 上下文引擎（近程消息 + 语义召回），working memory 跨对话用户记忆画像（可编辑可清空）与个人指令
- **知识库（RAG）**：文档自动分块 + PgVector 向量化检索、URL 抓取网页正文入库、分块内容回看，对话可挂载知识库引用回答
- **智能体 / AI 工具**：智能体创建即注册为一等 Mastra Agent（可作评测目标、可在 Studio 调试），附编程式内置智能体示例；HTTP 工具（函数调用）供对话与智能体调用外部接口
- **模型评测**：Mastra Datasets / Experiments 数据集版本化管理与异步实验，内置 ground-truth 与 LLM-as-judge 打分器，按打分器聚合与逐条结果对比
- **Mastra Studio**：经官方 Hono 适配器挂载 Mastra 标准 API，开发一键起 / 生产静态部署，对话 / 智能体 / 评测 / 工作流全链路 traces 可观测（敏感数据自动脱敏）
- **提示词模板**：可复用提示词模板管理，对话中一键套用
- **用量统计**：按模型 / 用户统计 Token 用量，支持日期范围查询
- **对话审计 / AI 反馈**：管理端对话内容审计查询、用户反馈收集与处理，上下文回放复用聊天渲染组件（思维链 / 图片 / 模型标注一致展示）

### 数据分析

- **行为分析**：用户行为 / 事件埋点分析
- **数据管理**：分析数据查询与维护
- **错误监控**：前端错误上报与 SourceMap 堆栈还原

### 报表中心（BI）

- **数据源 / 数据集**：多数据源接入与数据集建模（可视化 SQL）
- **仪表盘 / 数据大屏**：拖拽式仪表盘搭建（联动、钻取、条件格式）、收藏、订阅推送与嵌入分享；自由画布数据大屏，等比自适应缩放与深色科技皮肤
- **打印报表 / 填报**：打印模板设计（Univer 单元格设计器、套打）、数据填报模板与填报记录
- **数据治理**：指标中心、数据质量规则、数据预警、查询配额与 SLA、资源治理与资产目录
- **智能问数（ChatBI）**：自然语言查询数据

### 支付中心

## 快速开始

**前置条件**：Node.js 24.x、PostgreSQL、Redis

### 1. 安装依赖

```bash
npm install
```

### 2. 配置环境变量

在 `packages/server/` 目录下创建 `.env` 文件（参考 `packages/server/.env.example`），最小配置如下：

```env
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/zenith_admin
JWT_SECRET=your-secret-key
REDIS_URL=redis://127.0.0.1:6379
```

前端默认请求 `http://localhost:3300`，如需修改，在 `packages/web/` 下创建 `.env` 并设置 `VITE_API_BASE_URL`。

### 3. 初始化数据库

```bash
npm run db:migrate   # 执行数据库迁移
npm run db:seed      # 填充初始数据（创建默认 admin 账号）
```

### 4. 启动开发服务器

```bash
npm run dev            # 同时启动前端 + 后端（推荐）

npm run dev:server     # 仅启动后端
npm run dev:web        # 仅启动前端
```

默认账号：`admin` / 密码：`123456`

### 5. 生产构建

```bash
npm run build          # 顺序构建：shared → server → web
```

构建产物：后端 `packages/server/dist/`，前端 `packages/web/dist/`。

> 完整部署说明（Docker、Nginx 反代等）参见文档站：[快速开始](https://iwangbowen.github.io/zenith-admin/guide/getting-started)。
